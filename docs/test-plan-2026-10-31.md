## Hardware procedure

1. Copy and extract the complete V4 ZIP to a stable local folder on the cafe PC. Keep that folder and its journal through every retry.
2. Run `powershell.exe -NoProfile -ExecutionPolicy Bypass -File .\Test-CafePrinters.ps1` from that folder. Save `runtime/hardware-report.json`. Confirm Windows x64, both exact printer queues and drivers, USB CP001, Bluetooth COM3, and the installed paper forms.
3. Load and physically confirm the Hybsk 2.25 x 1.25 inch stock (57.15 x 31.75 mm; driver form 57 x 32 mm). Confirm the customer queue is `POS80 Printer`, the barista queue is `Y813BT Sticker`, and both devices are powered on.
4. Run `powershell.exe -NoProfile -ExecutionPolicy Bypass -File .\Test-CafePrinters.ps1 -Simulate`. This sends no physical jobs.
5. Run the same command with `-PrintTest` instead of `-Simulate`. Check one marked customer receipt and the barista labels: same folio, correct cup identity, accents, milk, no-ice instruction, final notes, margins and feed. Multiple identified continuation labels are allowed for long text.
6. Repeat the same physical command in the same folder. Accepted copies must not submit again. Inspect the Windows queues and paper before any further action if the result is uncertain; keep all journal files.
7. Run `-PrintTest -TestCase repeat-02` and then successive cases through `repeat-20`, waiting for existing jobs to drain between orders. Record missing output, duplicates and actual timing.
8. Exercise `bluetooth-offline`, `usb-offline`, `paper-out` and `long-notes` cases individually. Create the named physical fault deliberately; the case name only selects a saved sample order. Restore the device/paper and repeat the same case in the same folder. Windows may already own an accepted offline job. Inspect its existing queue instead of replacing it.
9. Retain `runtime/windows/result-<case>.json`, `last-result.json` and the complete SQLite journal. Photograph representative paper and record pass/fail for each case. Stop the program before backing up its SQLite files.

See [printing configuration and recovery](printing.md) for exact behavior. Simultaneous dispatch does not guarantee both devices finish printing at the same instant.
